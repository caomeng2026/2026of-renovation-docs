要点：
1. **不再有**封面顶部"四川省省级机关办公用房维修项目"眉题行（旧版有，新版删除）。
2. **副题只写"初步设计"**，不写"办公用房维修项目初步设计"（前缀已去掉）。
3. 项目名行字号 22pt→**26pt**，与"初步设计"同号。
4. **设计单位为新增行**：位于"建设地点"与"编制时间"之间，单位名称先留白——**冒号后预留 16 个全角字符（16 字）空位**，使整体排布更好看，后期手工填写（2026-09-03 用户约定）。**对齐方式：两端对齐（`w:jc w:val="both"`）+ 首行缩进 4 字符（`w:firstLineChars="400"`，即 `w:firstLine="1285"`）**，区别于其余信息行（项目单位/建设地点/编制时间为居中 CENTER）——2026-09-03 用户手动调整后约定，以后所有文档设计单位行一律照此对齐。
5. 编制时间**固定写"二〇二六年八月"**（用户约定 2026-09-03：编制日期统一都是八月，以后的文档一律如此，不随实际制作/交付月份变化）。
6. 封面信息行 run 未显式设 rFonts 时继承 Normal（须保证 Normal 样式 eastAsia=仿宋_GB2312，否则会渲染成宋体/等线）。

## 编制说明页版式（2026-09-03 用户约定）

- 标题"编 制 说 明"（22pt 加粗居中）。
- 正文为若干条编制依据/内容说明段落。
- **页末只保留落款日期**（如"二〇二六年八月"，右对齐），**不写"项目单位（盖章）：××××"行**（2026-09-03 用户约定：编制说明页不需要项目单位，只保留日期）。

## 字体

- 全文使用仿宋_GB2312，包括正文、标题、表格、目录、页眉、页脚、超链接、域代码。
- 字号：正文小四号（12 pt）；一级标题三号（16pt）；二级标题四号（14pt）。

## 标题与正文段落格式（2026-09-04 用户调整排版后固化）

以下"固定行距"均为**固定值 exact**（脚本 `pf.line_spacing = Pt(X)` + `line_spacing_rule = EXACTLY`，对应 OOXML `w:spacing w:line=<X*20> w:lineRule="exact"`）。

| 层级 | 字号 | 加粗 | 对齐 | 固定行距 | 段前 | 段后 | 缩进 |
|------|------|------|------|---------|------|------|------|
| 一级标题（第X章，Heading 1） | 16pt(三号) | 是 | 居中 | 26pt | 12pt | 8pt | 无 |
| 二级标题（X.X） | 14pt(四号) | 是 | 左对齐 | 24pt | 6pt | 4pt | 无 |
| 正文段落 | 12pt(小四) | 否 | 两端对齐 | 24pt | 0 | 0 | 首行缩进 2 字符（firstLine=480） |
| "编 制 说 明" / "目    录"标题 | 22pt | 是 | 居中 | 26pt | 6pt | 12pt | 无 |
| 编制说明落款日期 | 14pt(四号) | 否 | 右对齐 | 24pt | 18pt | 0 | 无 |

> 说明：封面主标题/"初步设计"为 26pt 固定行距 40pt、副题为 22pt 固定行距 36pt、信息行为 16pt 固定行距 34pt，见「封面版式标准」表。

## 章节分页规则（2026-09-09 用户调整后固化，后续所有项目照此）

1. **每章另起一页**：第一章紧接目录页（目录之后已有分页符）；**第二至第十章，每章标题（Heading 1）前插入一个分页符段落**。
2. 分页符段落结构：Normal 样式、空文本、含 `<w:br w:type="page"/>`，字号 **16pt**（`w:sz w:val="32"`，与章标题同号，避免占过大高度）。
3. 脚本实现：每章 `h1(...)` 调用前先执行 `page_break()`，即 `p = doc.add_paragraph(); r = p.add_run(); r.add_break(WD_BREAK.PAGE); set_run_font(r, size=16)`。
4. 效果：正文从第一章起，每章独立成页，页面干净规整。

## 页码规则

1. 分三节：
   - 第一节：封面（无页脚、无页码）
   - 第二节：编制说明（无页脚、无页码）
   - 第三节：目录及正文（有页脚、有页码）
2. 第三节页脚右下角：`第 PAGE 页/共 SECTIONPAGES 页`
3. `SECTIONPAGES` 只统计本节页数，因此"共X页"为目录起的总页数。
4. 目录页 = 第 1 页（`pgNumType start="1"`）。
5. **【关键坑】python-docx 遍历 `doc.sections` 并访问 `section.footer.paragraphs` 会重建节1/节2 已删除的 footerReference**（导致封面/编制说明被加上页脚引用）。正确顺序：全文统一字体的 fix 函数只处理节3（`doc.sections[2].footer.paragraphs`）→ 最后再删除节1/节2 的 footerReference → 保存。

## 目录规则

1. 使用 Word 自动目录域 `TOC \o "1-1" \h \z \u`。
2. **【关键】章节标题必须使用 heading 1 样式**（段落 pPr 中 `<w:pStyle w:val="<文档内heading 1的styleId>"/>`），否则 TOC 域 `\o "1-1"` 只按内置样式 Heading 1 抓取、抓不到任何标题，「更新目录」表现为无反应/报错"未找到目录项"/按钮灰色。**styleId 不固定**：python-docx 默认模板为 `Heading1`，WPS 保存的文档常为 `3` 或 `000008` 等，需读 styles.xml 按 `w:name w:val="heading 1"` 匹配。改样式时同时显式保留 run 的 rPr（仿宋_GB2312、sz）以免外观变化。
3. "目录"、"编制说明"等标题不使用 Heading 样式，避免被收录。
4. 目录条目带超链接书签，Ctrl+点击可跳转。
5. 条目与页码之间使用点线引导（制表位 leader=dot）。
6. **【关键】所有超链接条目必须包裹在 TOC 域内**：首条目前插 `fldChar begin`（`w:dirty="true"`）→ `instrText`（TOC 域代码）→ `fldChar separate`，末条目后插 `fldChar end`。否则 Word/WPS 识别不出"目录"，「引用→更新目录」按钮为灰色不可用。修复脚本：`scripts/fix_toc_domain.py`。
7. `settings.xml` 必须含 `<w:updateFields w:val="true"/>`（插在 `characterSpacingControl` 自闭合标签之后），打开文档时自动提示刷新目录页码。
8. **WPS 重新保存的文档**常丢失 updateFields、去掉 dirty 标记、把 `w:hyperlink` 标签转成 `HYPERLINK \l` 域（fldChar 结构仍在）——此时目录"不能更新"的排查顺序：① 标题是否 heading 1 样式（最常见根因）；② TOC 域 fldChar 是否完整；③ updateFields/dirty 是否缺失。一键修复脚本：`scripts/fix_desktop_toc.py`（含补 TOC1 样式，保证更新目录后条目仍为仿宋_GB2312+点线制表位）。

9. **目录项视觉规格（2026-09-09 用户调整后固化）**：目录条目使用 Word 内置 "toc 1" 样式（段落 `pStyle w:val="26"`，半隐藏内置样式，无需在 styles.xml 显式定义）；制表位=右对齐 + 点线引导（`leader="dot"`）+ 位置 **`pos="8845"`** twips（≈15.6cm，比旧脚本 15.0cm 略宽）；条目字号 **12pt**（`w:sz w:val="24"`）仿宋_GB2312。
10. **书签改用 Word 内置 `_TocXXXX`**（Heading 1 样式自动生成），不再使用旧脚本的 `_TOC_CS_N` 自定义锚点。即：目录条目 = `HYPERLINK \l _TocXXXX`（章节文字）+ tab + `PAGEREF _TocXXXX \h`（页码），全部包裹在 `TOC \o "1-1" \h \z \u` 主域内。

## 进度安排表（2026-09-04 起为必填项）

1. 每个项目初步设计文档**必须包含进度安排表**，位置在第八章 8.2「进度安排」正文之后、8.3「招标方案」之前。
2. 结构：6 行 × 3 列（表头「阶段 | 时间安排 | 主要工作内容」+ 5 个阶段数据行）。
3. 格式：全表仿宋_GB2312 10.5pt；表头加粗；「阶段」「时间安排」列居中，「主要工作内容」列左对齐；表格样式 Table Grid（全网格边框）。
4. 阶段划分：施工准备 → 各分项施工（按项目实际分项）→ 竣工验收；各分项可合理搭接，各阶段时间合计 = 工期。
5. **【关键】工期必须先询问用户确定**：每个项目的工期（日历天数）以用户确认为准，不得自行假设；确定后再据此划分阶段时间。示例（270 日历天）：施工准备第1个月 / 分项A第2—4个月 / 分项B第3—6个月 / 分项C第5—7个月 / 竣工验收第8—9个月。
6. 8.2 进度安排正文引导句："项目计划工期XXX日历天。拟按以下阶段组织实施，主要进度安排如下表："。
7. 三处工期一致：进度表阶段合计、「项目基本情况表」"建设工期"栏、「项目申报审批模板」工期栏须同步。

## 生成脚本演进经验（2026-09-07 用户明确要求：参考已定稿项目调整格式）

**易踩坑**：复制旧 gen_xxx_doc.py 制作新项目时，常常只复制"项目数据"和"章节内容"，**忘了复制格式定义函数**（h1 / h2 / h3 / para_design_unit / add_table 带灰底 / heading 等）。结果生成的 docx 看上去与项目-LZ/单位-FGX已定稿版本差距较大——原因是标题段落的 `paragraph_format` 没附加 `space_before / space_after / line_spacing` 属性。

**正确做法**（已固化到 gen_jq_wq_doc_v2.py）：

1. **必须把以下函数整套照搬**到新生成脚本：
   - `h1(text)` / `h2(text)` / `h3(text)` — 三级标题函数，不要用 `add_paragraph(style='Heading 1')`
   - `para_design_unit(text)` — 封面设计单位行（两端对齐 + 首行缩进 4 字符）
   - `add_table(headers, rows, ...)` — 表头自动加灰底 E7E6E6
   - `heading(text, size=22)` — 编制说明/目录专用 22pt 标题
   - `set_run_font(run, size, bold)` — 设置 ascii/hAnsi/eastAsia/cs 四套 rFonts

2. **不要直接用 `doc.add_paragraph(style='Heading 1')`**，因为这只是套上样式，**不会**附加段前 12pt / 段后 8pt / 行距 26pt 等 paragraph_format 属性（python-docx 不会自动套用样式内的段落属性）。

3. **跨项目格式一致性自查清单**（生成后用 verify_xxx.py 校验）：
   - 节数 == 3（封面 + 编制说明 + 正文/目录）
   - 表格表头灰底 == True（首个 cell 的 tcPr/w:shd/@w:fill == 'E7E6E6'）
   - Heading 1 段落全部带 sb=152400(12pt) sa=101600(8pt) ls=330200(26pt) 属性
   - 二级标题段落全部带 sb=76200(6pt) sa=50800(4pt) ls=304800(24pt) align=LEFT 属性
   - 页脚 only on 第三节（封面/编制说明 footerReference 必须删除）
   - 封面"设计单位"行两端对齐 + firstLineChars=400
   - 编制说明页末只有日期，无"项目单位（盖章）"行
   - TOC 域用 `\o "1-1"`（只列一级），Heading 1 标题含 `_TOC_CS_N` 锚点

4. **存在格式差距时**，按以下流程操作：
   - ① 比对两份 docx 的 paragraph_format 属性（H1/H2/H3、表格灰底、节数）
   - ② 拷贝"参考定稿"的整套格式定义函数到 v2 脚本
   - ③ 用 python-docx 替换项目数据后重新生成
   - ④ 用 verify 脚本与定稿逐字段对比，关键属性（H1 sb/sa/ls、表格灰底、节数）必须完全一致
   - ⑤ present_files 前先把旧版备份到 `.workbuddy/workspace/compare/<项目>_v1_<日期>_backup.docx`，方便回退

5. **重要**："文档修改保护原则"仍生效——若用户已手动修改过 docx，**只重写脚本、不覆盖文件**，先问"是覆盖还是只改某处"。本次围墙文档在用户验收后立即重新生成（无手动修改痕迹），属安全覆盖；下次生成其他项目格式不一致时，仍按以上流程走。
